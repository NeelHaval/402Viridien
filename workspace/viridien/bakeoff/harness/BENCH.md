# One benchmark API

Run from `bakeoff/`, with the repository's Python environment. Paths in
`harness/suites.json` are relative to the repository, on Windows and Linux.
`LITHOLOGY_DATASET` selects the original dataset; the normal harness dataset
resolver supplies its default. No VM or Windows paths are embedded in the API.

```bash
python -m harness.bench --strategy s11,s12 --suite viridien_eval,ext_dev --workers 2
python -m harness.bench --strategy s11,s12 --suite ext_test --workers 2
python -m harness.bench --strategy s11 --suite ext_dev --compare-to out/bench/RUN_ID
python -m harness.bench --strategy s11 --suite ext_dev --min-layer-px 8
python -m harness.bench --strategy s11 --suite ext_dev --no-cache
```

External test is for the final evaluation only. Never use its scores, or the
13 in-domain evaluation logs' truth, to choose strategies or thresholds. Use
development wells with grouped cross-validation and synthetic data. `ext_shared`
is public development data and is not independent held-out evidence.

The registry contains `viridien_eval` (gold takes precedence, otherwise a
pixelwise consensus of silver labelers, ties resolved in sorted labeler order),
`viridien_gold` (the gold-tier log06 window), `synthetic` (three deterministic
4000-row columns per evaluation log, generated by `synth.make`, seed zero),
`ext_dev`, `ext_test`, `ext_shared` (the separately published `external_shared/` subset), `round3`, and `unlabelled`.
Synthetic truth is generated alongside the pixels; the registered synthetic
truth directory documents the existing harness layout and is not read as
hand-labelled truth. Missing optional dataset roots give a clear error.
When a present optional dataset has no items file, its annotated images become
full-column windows. An absent image or truth file produces a failed result
row; `unlabelled` intentionally never reads or scores truth.

Every registry path has an explicit environment override where relevant. For
example, `BENCH_EXTERNAL_DATASET`, `BENCH_EXTERNAL_TRUTH`,
`BENCH_EXTERNAL_MANIFEST`, `BENCH_EXTERNAL_SPLITS`, and `BENCH_EXT_DEV_ITEMS`
select external inputs independently. Set all relevant paths when relocating
a suite. `LITHOLOGY_BENCH_REGISTRY` can point to a replacement registry.
Entries can inherit using `extends` and can define `per_log` metadata overrides.
Items can also contain `source`, `well`, and `family`. Precedence is item,
per-log override, manifest CSV, suite default. Manifest rows use `id` or `log`.
Missing family metadata is explicitly `unknown`; no geological or visual
families are inferred from labels or scores. Missing well metadata uses the
log identifier, removing `_logNN...` for continuation logs. These are proxy
bootstrap units, so supplying real well identifiers improves the estimates.

The guard refuses suite names containing `verify` and items whose log or
metadata mentions any well/log declared under a verify split. It checks both
the canonical external split declaration and any configured split declaration,
before opening images or truth. `--unseal` is an explicit override; the Python
equivalent is `unseal=True`. The API does not discover or reconstruct removed
datasets. The guard checks metadata as well as the entire original items list,
before a tier or shared-subset filter can hide a sealed identifier.

String or list arguments select multiple suites and strategies. Local functions
and closures are serialized with `cloudpickle`; process workers use `spawn`
for portability. In scripts, call `evaluate` inside an
`if __name__ == '__main__':` block. Additional keyword options include
`registry`, `out_dir`, `cache_dir`, `render=False`, `no_cache=True`, and
`compare_to`. `out_dir` should be a fresh directory for each run.

The shared machine budget caps concurrent worker processes at four. Numerical
thread counts are bounded at one per worker, including explicit thread increases attempted
by a strategy. CPU inference is used consistently. Two workers are a practical
default for the shared VM's memory allowance. Source reads and overlays use
the harness's strip-safe loader; predictions never require converting the whole
page to RGB. Cache hits avoid opening or decoding source pages when an overlay
is already cached.

## Cache and failures

Predictions live under `out/_cache/bench/predictions`. Identity includes the
strategy file's SHA-256 (or serialized notebook callable), full window,
SHA-256 of image and annotation contents, log identity, synthetic seed/replicate,
CPU device, local harness/strategy/pipeline code, and pretrained `.pt` artifacts
under `emil/drive`. Each invocation streams source hashes once per image; source
arrays are not retained in the parent. This trades a small amount of file IO
for reliable invalidation even if a file's size or timestamp was preserved.
Changed installed third-party packages require `--no-cache` or clearing the
benchmark cache. Strategy-internal caches are isolated by strategy and dataset
hash, and shared legend/depth caches by dataset hash. Locks serialize creation
of those multi-file preprocessing caches. No benchmark cache can collide with
the legacy runner's basename caches.

Truth, minimum-layer threshold, and output suite names do not affect prediction
identity: cached intervals are always rescored against current truth. Overlays
have a separate key containing truth and scoring settings. Cache hits retain
original strategy `seconds`; `wall_seconds` measures actual task time. Failed
predictions are not cached. `--no-cache` bypasses benchmark prediction/overlay
reads and writes; the underlying legend/depth and strategy preprocessing caches
remain available. Cache writes use atomic replacement.

Every task catches preprocessing, inference, scoring, and rendering exceptions,
retains the traceback, and records `failure=True`. Scored failures have zero
`score`, `row_acc`, `boundary_f1`, and `cluster_ari`; depth error is undefined.
They remain in accuracy denominators. Unlabelled failures have no quality
scores. Empty prediction CSVs and failure overlays are written when input
images are available. Worker-process exceptions also become failed rows.
`progress.jsonl` checkpoints completed windows before final aggregation.

## Outputs and statistics

Each `out/bench/RUN_ID/` contains:

- `results.json` and `results.csv`: one row per strategy/suite/window/replicate;
  metadata, all five quality metrics, original inference time, wall time,
  sampled strategy RSS, API calls, cache status, failure and traceback.
- `summary_suite.csv`, `summary_source.csv`, `summary_family.csv`: means and
  bootstrap 95% confidence intervals, metric sample count, well count,
  window count and failure count. The same tables appear in `results.json`.
- `predictions/*.csv`, `overlays/*.png` and `*_thumb.png`: standard interval
  outputs and prediction/truth/source/legend figures made with `harness.viz`.
- `report.html`: flat, white, mobile-readable tables, lazy-loaded thumbnails
  linked to full overlays, and expandable failure tracebacks.
- With `--compare-to`: `comparison.json`, `comparison_windows.csv`, and
  `comparison_summary.csv`, also included in the HTML report.

Means weight windows equally. Confidence intervals use 2000 deterministic
percentile-bootstrap draws (seed zero) of **whole wells**, repeating all windows
of each sampled well. This preserves within-well dependence. One observed well
gives a degenerate interval; missing metric values are omitted. Source/family
summaries pool the selected suites, so overlapping suites such as `ext_dev`
and `ext_shared` repeat those windows if requested together.

Comparisons match suite/log/y0/y1/replicate, and strategy name when either side
has multiple strategies. Single-strategy DataFrames may compare different
strategy names. Duplicate keys, inconsistent well metadata or different
minimum-layer settings are refused. Deltas are current/A minus baseline/B;
wins/losses use the better direction, including lower depth error, time, RSS
and API cost. Unmatched windows are counted and excluded from paired estimates.
Paired confidence intervals resample whole wells using the per-window deltas.

## Thin layers and compatibility

`score.score(pred, truth, window, min_layer_px=K)` and both runner CLIs accept
the option. Default zero takes the original scoring path unchanged. A positive
integer clips intervals to the window, then repeatedly absorbs the shortest
interval thinner than K into a touching neighbour, preferring the thicker
neighbour and breaking ties upward. Isolated intervals never bridge blank
gaps; a sole thin interval remains. Outer boundary depths are preserved when
available. Inputs are copied; raw prediction CSVs retain original intervals,
while benchmark overlays show the intervals actually scored. The legacy
runner's existing JSON schema is unchanged unless the new option is nonzero.

```bash
python -m pytest harness/test_bench.py harness/test_score.py harness/test_run.py -q
```

Compatibility validation reruns the legacy `_dummy` command on the original
log06 gold window, before and after the additive scorer/runner edits. Compare
per-window and mean values for `score`, `row_acc`, `boundary_f1`, `cluster_ari`,
and `depth_mae_ft`; timing and RSS naturally vary. The run artifacts are under
`out/_dummy/api_compat_before` and `out/_dummy/api_compat_after`.
