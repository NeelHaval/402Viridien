## Reproduced defects and fixes

| Reproducer | Before | After |
| --- | --- | --- |
| Concurrent identical uploads with different bbox input | Second caller could fail an SQLite uniqueness check after overwriting the first job's sidecar. | Atomic single-service submission; conflicting bbox returns 409 and preserves first inputs. |
| Deeply nested 10,007-byte bbox JSON | Real FastAPI request returned HTTP 500. | Controlled HTTP 400; finite geometry/schema checks precede publication. |
| Oversized or understated-length streamed multipart body | Endpoint limit ran after framework spooling. | Measured body cap, standardized 413 and closed partial spools. |
| Stream read/write failure during upload | Partial incoming file could remain. | Exclusive UUID path creation and owned partial-file cleanup; existing files survive collisions. |
| Fractional/infinite/complex coordinates, malformed cluster IDs or labels | Output validator accepted several invalid tables or cast them unsafely. | Strict real integer/signed-64-bit/label validation before casts. |
| One-pixel bed at 0.02 ft/px | Decimal rounding could turn both depth endpoints into 2.0. | Calibrated precision retained when rounding would erase thickness/order. |
| Two valid very large aggregation weights | Intermediate arithmetic could overflow to NaN. | Exact stable weighted means, preserving ties-to-even rounding. |
| Saturated or closing job queue; publication/scheduling failure | No admission bound and incomplete failure paths. | Default 32-slot admission before persistence; reservations, rollback, cancellation and retry tested. |
| Nonfinite stored values or enormous report depth span | JSON/API errors or unbounded report expansion. | Finite storage, bounded report complexity and clear 409 rejection. |
| Delayed initial well-list response after upload | Could remove the queued well and leave UI polling stuck. | Stale list responses ignored; pending uploads continue polling. |

The browser harness reproduced the list race before the fix (6/7 scenarios
passed) and passed all seven afterward. Its other scenarios cover empty state,
keyboard dismissal, failed requests, upload rejection/recovery, successful
queued-to-ready flow and CSV link, metadata rendered as text, and stale detail
responses. Its screenshots contain **fixture wells/scores**, not model results.

Independent reviewers checked the API changes and eight targeted ingest/queue
failure paths. Existing backend service/scoring/store and pipeline suites also
passed independently. No expected-failure markers conceal these defects.


fixtures remain ignored under `.runs/`; the curated JSON records measurements
and tested source without uploading real scan crops or local environment data.

on every push/PR. Real OCR stays opt-in.

## Remaining limits

This is extensive executable coverage, not an assertion that every possible
edge case is eliminated. Whole-job hard memory/deadline isolation remains
absent from the demo service. Image validation occurs before queue admission;
existing reader pixel/cache budgets can be large. One backend worker remains
the supported configuration. Browser map rendering uses a mocked style, and
model quality across all 54 scans/unseen wells was not measured in this retest.
Python dependencies were checked for consistency, not audited against CVEs.
The frontend bundle still triggers Vite's advisory large-chunk warning.
